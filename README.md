# SERS — نظام السجلات التعليمية الذكي

SERS (Smart Educational Records System) هو مشروع لإدارة الأعمال والتقارير والشواهد التعليمية. هذا المستودع `anas8273/sers-preview` هو مسار التنفيذ الحالي وفق [قرار المستودع والترحيل](docs/adr/0001-canonical-repository-and-migration-strategy.md).

آخر تحديث: 28 أكتوبر 2026. المشروع قيد التطوير؛ نجاح الاختبارات لا يعني إغلاق Pilot أو الجاهزية لاستخدام بيانات مدارس حقيقية.

## الرحلة المنفذة

حساب شخصي أو عضوية مدرسة مقبولة → سنة وفصل → عمل وتقرير محفوظ في الخادم → شواهد نصية وروابط وملفات مفحوصة → `WorkVersion` ثابتة → مراجعة واعتماد → PDF أو Word قابل للتعديل → رابط أو QR للنسخة المعتمدة.

- محرر التقرير يحفظ المسودة في MySQL، ويدعم الحفظ التلقائي وكشف تعارض التعديلات. النسخة المحلية وسيلة استعادة مؤقتة، وليست قاعدة البيانات الرئيسية أو ضمان مزامنة كاملة دون اتصال.
- `WorkVersion` snapshot ثابت؛ تعديل المسودة لا يغير النسخة السابقة. المراجعة والمخرجات ترتبطان بالنسخة المحددة.
- المشاركة العامة أو المحمية تستخدم token عشوائيًا، وانتهاءً اختياريًا وإلغاءً. كلمات المرور الجديدة تخزن بصيغة salted scrypt؛ التحقق من SHA-256 القديم للتوافق الانتقالي فقط.
- صفحة `/output/:token` تعرض حقول التقرير والشواهد المختارة فقط، دون روابط الأصول أو مفاتيح التخزين أو بيانات الملكية. يوجد حد طلبات في ذاكرة العملية، وليس حدًا موزعًا بين الخوادم.
- دمج [PR #31](https://github.com/anas8273/sers-preview/pull/31) في `main` عند `ac06f50` أغلق دفعة المشاركة الأساسية. لا يمثل الدمج نشرًا لبيئة تشغيل.

## حدود القدرات الحالية

| القدرة | الحالة |
|---|---|
| Work / Asset / Version / Review / Output | نواة خادمية وصلاحيات واختبارات عزل MySQL |
| مكتبة الشواهد الجديدة | إنشاء نص/رابط وإعادة استخدام الأصل وربطه بالأعمال |
| رفع ملفات الشواهد الجديد | واجهة استقبال واستئناف وإلغاء؛ تخزين POSIX خاص دائم، حصص وحجر وفحص فعلي عبر ClamAV وqpdf |
| الفحص والنشر والتنزيل والتنظيف | فحص البايتات الثابتة ثم نشر الأصل ذريًا؛ تنزيل مصادق ومصالحة وعامل تنظيف يراعي المراجع والحجز القانوني |
| PDF من WorkVersion | منفذ عبر خادم الرسم وعقد التخزين الحالي؛ يحتاج تحققًا بصريًا وتشغيليًا على بيئة النشر |
| Word من WorkVersion | فقرات وجداول عربية قابلة للتعديل من النسخة نفسها؛ تنزيل خاص محمي؛ مراجعة بصرية لست صفحات في LibreOffice |
| عضويات المدرسة | إنشاء مدرسة ودعوة حساب موجود وقبولها وتغيير الدور وتعليق العضوية مع حماية آخر مالك |
| السنة والفصل والإشعارات | إنشاء سنوات وفصول وربط الأعمال وتصفيتها؛ سياق تاريخي ثابت؛ إشعارات الرفع والمراجعة وقراءة معزولة للمستخدم |
| التكليفات المؤقتة والانتقال والأرشفة | خارج الدفعة الحالية |
| مساعدة AI وتصنيف الشواهد | دخول مطلوب، ميزانية دائمة وحدود موارد، نتائج مقترحة تحتاج مراجعة؛ التصنيف المحلي لا يرتبط ببند قبل القبول الصريح |
| التقويم الذاتي وخطة التحسين | ضمن المتطلبات التالية، وليستا قدرتين مكتملتين في النواة الجديدة |
| التشغيل والاستعادة | حاويات منفصلة للتطبيق والعامل وMySQL وClamAV، جاهزية ونسخ متسق وتجربة استعادة؛ UAT البشري والبيئة الخارجية باقيان |

**رفع الملفات وصور القوالب عبر المسارات القديمة متوقف** لأنها لا تطبق الحجر والفحص والحصص الخاصة. الرفع الجديد عبر `/evidence` هو المسار المدعوم؛ تبقى قراءة وحذف الملفات القديمة وتحرير المحتوى اليدوي متاحة. لا تصبح البايتات القديمة خاصة أو مفحوصة بأثر رجعي.

الأدوات القديمة للشهادات والسيرة والاختبارات والإذاعة وغيرها باقية أثناء الترحيل. لا تعد بديلًا عن رحلة vNext، ولا يفترض أن كل قدراتها القديمة تحقق عقود النواة الجديدة.

## التطوير المحلي

المتطلبات: Node.js 22، وإصدار pnpm المحدد في `packageManager`، وقاعدة MySQL مستقلة للتطوير. تشغيل الرحلات الخادمية يحتاج قاعدة بيانات ومصادقة مهيأتين؛ لا يوجد تسجيل دخول إنتاجي بديل ضمن اختبارات المتصفح.

```bash
corepack enable
pnpm install --frozen-lockfile
```

ينزل `postinstall` متصفح Chrome المطلوب لـPuppeteer. إذا عُطلت scripts أثناء تثبيت الاعتماديات، شغّل `pnpm exec puppeteer browsers install chrome` قبل اختبار PDF والمتصفح.

اضبط المتغيرات وفق `server/_core/env.ts` و`client/src/const.ts` في بيئة محلية غير متتبعة بـgit:

| المتغير | الاستخدام |
|---|---|
| `DATABASE_URL` | اتصال MySQL للتطوير أو بيئة التشغيل المقصودة |
| `JWT_SECRET` | سر جلسات مستقل وقوي للبيئة |
| `VITE_APP_ID` | معرف تطبيق المصادقة |
| `OAUTH_SERVER_URL` و`VITE_OAUTH_PORTAL_URL` | إعداد خادم وبوابة OAuth الحالية |
| `OWNER_OPEN_ID` | معرف مالك الإدارة عند الحاجة |
| `APP_PUBLIC_ORIGIN` | أصل HTTPS القانوني للتطبيق؛ عنوان callback مشتق منه ولا يعتمد على رؤوس الوكيل |
| `OAUTH_PORTAL_URL` | بوابة الدخول الخادمية؛ يمكن استخدام `VITE_OAUTH_PORTAL_URL` للتوافق |
| `SERS_HEALTHCHECK_TOKEN` | سر مستقل للوصول إلى تفاصيل صحة التشغيل والمقاييس؛ لا يمر في query string |
| `BUILT_IN_FORGE_API_URL` و`BUILT_IN_FORGE_API_KEY` | تكاملات Forge القائمة، ومنها تخزين المخرجات |
| `SERS_AI_ENABLED` | يفعّل المساعد عند القيمة `1` فقط؛ معطل افتراضيًا والعمل اليدوي متاح |
| `SERS_AI_USER_DAILY_LIMIT` / `SERS_AI_GLOBAL_DAILY_LIMIT` | حدود الطلبات المقبولة في اليوم UTC؛ الافتراضي 30 للحساب و300 للتطبيق |
| `SERS_AI_USER_MINUTE_LIMIT` | حد الحساب في الدقيقة؛ الافتراضي 5 |
| `SERS_AI_USER_CONCURRENCY` / `SERS_AI_GLOBAL_CONCURRENCY` | طلبان نشطان للحساب وثمانية للتطبيق افتراضيًا، عبر قاعدة البيانات |
| `PORT` | منفذ التطبيق، الافتراضي 3000 |

لا تضع الأسرار في متغيرات `VITE_*` أو في ملفات متتبعة. راجع [دليل التشغيل](docs/operations/STAGING_RUNBOOK.md) لإعداد التخزين الخاص وClamAV والحصص والأسرار. تستخدم الدفعة مزودًا خاصًا على قرص POSIX، ولا تقرر موقع استضافة بيانات المدارس أو سياسة الاحتفاظ بها. لا يفعّل الرفع بمجرد ضبط متغيرات Forge.

الدخول يبدأ من `/api/oauth/start` بمحاولة عشوائية مرتبطة بالمتصفح تنتهي بعد عشر دقائق وتستهلك مرة واحدة. الجلسة مرتبطة بالتطبيق وبسجل خادمي وتنتهي بعد سبعة أيام؛ تسجيل الخروج يلغيها في قاعدة البيانات. **الجلسات القديمة تحتاج تسجيل دخول جديدًا بعد هذه الترقية.** لا يُحفظ رمز المزود أو رمز الجلسة الخام في قاعدة البيانات. اختبار التدفق يستخدم مزودًا اصطناعيًا مستقلًا يطابق عقد Manus؛ لا يثبت تسجيل دخول لحساب خارجي حقيقي.

`/healthz` لحياة العملية، و`/readyz` للجاهزية العامة دون تفاصيل. `/api/operations/health` و`/api/operations/metrics` يحتاجان Bearer خاصًا. تشمل الجاهزية قاعدة البيانات والتخزين والفاحص وتقدم العامل عند إعدادها، وتظل تفاصيل الاستثناءات والروابط وأكواد الدخول خارج سجلات المراقبة. صورة التشغيل تحمل بصمة ملفات وعقد توافق للترحيلات والأعمدة؛ يُرفض تشغيل إصدار غير متوافق بدل تغيير البيانات ضمن الرجوع البرمجي.

الرفع يقبل PDF وPNG وJPEG وTXT حتى 16 MiB. يرفض PDF المشفر أو المحتوى النشط والأنواع غير المدعومة؛ فشل الفاحص لا ينشر الأصل. الفيديو وOffice المرفوع وCDR وإزالة EXIF ليست قدرات هذه الدفعة. إيقاف `SERS_UPLOADS_ENABLED` يمنع الطلبات الجديدة ويترك العامل يستكمل معالجة الطلبات القائمة.

Word الجديد يتطلب `SERS_PRIVATE_STORAGE_DIR` صالحًا ولا يعود إلى التخزين القديم. PDF القديم يحتفظ بالتوافق مع Forge عند عدم إعداد المزود الخاص؛ لا يُستنتج من ذلك تحقق خصوصية المزود القديم.

طبّق الترحيلات الموجودة على قاعدة تطوير فارغة، ثم شغّل التطبيق:

```bash
pnpm exec drizzle-kit migrate --config drizzle.config.ts
pnpm dev
```

راجع أي ترحيل جديد قبل تطبيقه. الأمر `db:push` في المشروع يجمع التوليد والتطبيق؛ ليس خطوة تشغيل إنتاجية تلقائية.

  --exclude server/performance-evidence.test.ts \

  --exclude server/copy-templates-barcode.test.ts \

تتخطى اختبارات MySQL المتخصصة التشغيل دون `SERS_INTEGRATION=1`. ذلك ليس دليل نجاح لها؛ تشغّلها بوابة GitHub Actions على قاعدة مؤقتة معزولة، وتتحقق اختبارات الرفع من اسم القاعدة وإصدار MySQL وهوية بيئة CI قبل كتابة fixtures.

| البوابة | الإثبات |

رحلة المتصفح إلى MySQL تستخدم هوية اصطناعية داخل خادم الاختبار فقط. لا تثبت مصادقة OAuth الإنتاجية أو التخزين السحابي أو مسح QR بجهاز فعلي أو جودة طباعة كل المستندات.

رحلة `auth-mysql` الإضافية تمر بمسارات الدخول وملفات cookie والجلسات الفعلية للتطبيق، مع مُصدر هوية اصطناعي منفصل؛ لا تحقن المستخدم في سياق التطبيق. وتختبر بوابة المستندات استخراج النص الطويل وحدود صفحات PDF وفك QR رقميًا من PDF وWord، وتحفظ ملفات اصطناعية قابلة للمراجعة ضمن مرفقات CI.

## خطة الإكمال

1. تشغيل بيئة خارجية ببوابة OAuth حقيقية وسياسة موقع بيانات واحتفاظ معتمدة.
2. UAT بأدوار متعددة، وفتح وتعديل Word في Microsoft Word، وتجربة أجهزة وطباعة ومسح QR فعلي.
3. ربط التنبيهات التشغيلية وتحديد مسؤول الحوادث وRTO/RPO وحماية الفروع الإلزامية.
4. التكليفات والانتقال والأرشفة والوحدات اللاحقة وفق سجل المتطلبات.

ابدأ من [بوابات الدخول والتشغيل والمخرجات](docs/vnext/14_AUTH_RUNTIME_AND_OUTPUT_GATES.md)، و[دفعة الرحلات الأساسية](docs/vnext/13_CORE_JOURNEYS.md)، و[سجل القرارات](docs/vnext/03_DECISION_REGISTER.md). الوثائق المؤرخة تصف حالة دفعتها؛ وصف PR ونتائج CI على SHA محدد هما مرجع تحقق التحديث نفسه.

## حدود AI والوسائط والرفع القديم

تفاصيل الدفعة ومصادرها في [بوابات AI والوسائط](docs/vnext/15_AI_MEDIA_AND_LEGACY_SAFETY.md). كل عمليات `ai` و`genAI` تتطلب جلسة صالحة وأصل طلب مطابقًا لإعداد الخادم. الحدود الدائمة تحسب الطلب المقبول حتى لو فشل المزود، ولا تعني تسعيرًا أو ضمان تكلفة نقدية. النقل محدود بـ45 ثانية و4096 رمز إخراج كحد أعلى؛ مهلة السجل أطول وتتحقق قبل بدء المزود لمنع استخدام حجز منتهي. تسجل بيانات العملية والمزود والنموذج وإصدار التعليمات والاستخدام المبلغ عنه، دون نص الطلب أو الرد أو صورة المستخدم.

اقتراحات التصنيف تحفظ محليًا منفصلة عن البنود. لا ربط أو تعلم من الاقتراح قبل قبول المستخدم، والاقتراح منخفض الثقة لا يحدد وجهة مسبقًا. ملفات الانتظار وسجل التعلم الجديد مقيدان بالحساب والوظيفة؛ تعذر IndexedDB يبقي الملف دون اعتماد ويعرض حدود الحفظ. لا ينشئ AI شهادة حضور أو إنجازًا فعليًا عند فشل تفسير الرد. هذه حوكمة للأدوات القديمة، وليست إغلاقًا لوحدة Smart Evidence المؤسسية كاملة.

وكيل الصور يقبل PNG/JPEG فقط، يفك الصورة ويعيد ترميزها إلى PNG دون metadata، بحد 6 MiB و8 ملايين بكسل ومهلة كلية 8 ثوانٍ. GIF/WebP وSVG ليست مدعومة في هذا المسار. التصدير مشترك في قائمة محدودة؛ PDF حتى 80 صفحة، وWord المرئي القديم حتى 20 صفحة. Word الأصلي من WorkVersion يبقى نصًا قابلًا للتحرير. لا يُقص المحتوى لتجاوز الحد؛ يفشل الطلب بوضوح.

روابط المشاركة القديمة الجديدة بكلمة مرور تستعمل scrypt مملحًا (ستة أحرف على الأقل)، وتحتفظ بقراءة الروابط القديمة. حجز المشاهدة ذري وتُعاد مراجعة الإلغاء قبل الإرجاع. حد محاولات الوصول في ذاكرة العملية؛ لا يدعي توزيعًا عبر نسخ خادم متعددة.
