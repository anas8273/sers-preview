# تشغيل SERS ذاتيًا واختبار الاستعادة

هذا المسار يشغّل MySQL 8.4 والتطبيق وعامل صيانة مستقل وClamAV حقيقيًا. التخزين الخاص مجلد POSIX دائم؛ يحتوي الشواهد ومخرجات PDF وWord. لا توجد خدمة تخزين عامة أو تجاوز لتسجيل الدخول في خادم التطبيق.

## المتطلبات والحدود

- مضيف Linux مع Docker Engine وCompose v2، وذاكرة 8 GB على الأقل ومساحة كافية للصور والنسخ الاحتياطية. يحتاج ClamAV ذاكرة تصل إلى 4 GB وتنزيل تحديثات التواقيع.
- لأوامر النسخ والاستعادة على المضيف: Node 22، وpnpm 10.4.1، وPython 3.12 أو أحدث، وGNU tar وutil-linux. نفّذ `pnpm install --frozen-lockfile --ignore-scripts` داخل المستودع.
- الصورة تثبّت Chromium وqpdf وflock وprlimit. التطبيق والعامل يعملان بالمستخدم `10001:10001` ونظام ملفات للقراءة فقط، مع `/tmp` مؤقت محدود.
- الإعداد مخصص للتجربة والاستعداد للتشغيل. عناوين الصور تتبع إصدارًا رئيسيًا/فرعيًا؛ ثبّت digests في سجل إصدار معتمد قبل اعتماد نشر دائم.
- لا يشمل هذا الدليل إنشاء حساب OAuth أو نشرًا خارجيًا أو شهادة TLS أو سياسة احتفاظ تنظيمية. لا تُعرض MySQL أوClamAV للإنترنت.

## بيئة staging بتسجيل دخول OAuth الفعلي

نفّذ من جذر المستودع. المعرّفات والعناوين التالية يجب أن تكون تخص تطبيق OAuth المسجل لديك؛ ليست بيانات دخول جاهزة.

```bash
export SERS_SECRETS_DIR=/var/tmp/sers-staging-secrets
node scripts/operations/init-secrets.mjs "$SERS_SECRETS_DIR"
export SERS_DATABASE_NAME=sers_staging
export VITE_APP_ID='YOUR_REGISTERED_STAGING_APP_ID'
export VITE_OAUTH_PORTAL_URL='https://YOUR_OAUTH_PORTAL'
export OAUTH_SERVER_URL='https://YOUR_OAUTH_SERVER'
docker compose -f compose.staging.yml config --quiet
docker compose -f compose.staging.yml build app
docker compose -f compose.staging.yml up -d --wait --wait-timeout 600 mysql clamav
docker compose -f compose.staging.yml run --rm migrate
docker compose -f compose.staging.yml up -d --wait --wait-timeout 240 app worker
curl --fail http://127.0.0.1:3000/readyz
```

`init-secrets.mjs` ينشئ ثلاثة أسرار عشوائية في ملفات `0600` داخل مجلد `0700` خارج المستودع ويرفض استبدالها. يحتفظ MySQL بكلمة مروره داخل حجمه الدائم؛ تغيير ملف السر وحده ليس تدويرًا لكلمة مرور قاعدة موجودة. خدمة `storage-init` بلا شبكة تجهز ملكية حجم الشواهد وتنسخ سري التطبيق فقط إلى حجم خاص بالمستخدم `10001` تقرؤه الخدمات بوضع القراءة فقط. لا يصل سر MySQL الجذري إلى التطبيق.

التطبيق متاح على `127.0.0.1:3000`. عند الحاجة إلى وصول خارجي، ضع وكيل TLS معتمدًا أمام هذا المنفذ واضبط عنوان callback في OAuth. `/healthz` يثبت حياة العملية، و`/readyz` يثبت اتصال قاعدة البيانات فقط. افحص أيضًا صحة خدمة `clamav` والعامل ونجاح رفع اصطناعي؛ الجاهزية لا تثبت عمل OAuth أو الفاحص.

حدود staging محددة في Compose: 256 MiB للحساب الشخصي، و1 GiB للمدرسة، و20 طلب رفع نشطًا لكل نطاق. هذه قيم اختبار صريحة وليست سياسة إنتاج افتراضية. حد الملف 16 MiB. ينشأ سجل الحصة عند أول طلب مصرح، وتعديل متغير البيئة لاحقًا لا يغير حصصًا موجودة تلقائيًا.

العامل يقرأ سجل نطاقات الحصص بصفحات من100 نطاق، ويمر بالتتابع على انتهاء الصلاحية ثم المصالحة ثم الفحص والتنظيف. ينتظر10 ثوانٍ بعد الدفعة؛ لا توجد دفعات متداخلة. يعالج مرشح استقبال وفحص وتنظيف واحدًا لكل نطاق في الدورة، ويوقف نفسه عند توقف التقدم120 ثانية. تستعيد عقود قاعدة البيانات العمل بعد إعادة التشغيل. سجلاته أعداد فقط دون مفاتيح تخزين أو أسماء مستخدمين. تعطيل الاستقبال الجديد مع استمرار التصريف:

```bash
export SERS_UPLOADS_ENABLED=0
docker compose -f compose.staging.yml up -d app worker
```

لا تشغّل أكثر من نسخة من العامل دون مراجعة السعة. لا تستخدم NFS أو مجلدًا مكشوفًا عبر خادم ملفات للتخزين الخاص، ولا تغير صلاحياته إلى `0755`.

## عرض اصطناعي محلي مستقل

`compose.demo.yml` مشروع مختلف باسم `sers-demo` وحجوم مختلفة. يستخدم خادمًا مستقلًا من `scripts/operations/demo-server.mts`، خارج حزمة `dist/index.js` الإنتاجية. يرفض `NODE_ENV=production`، ويرفض أي قاعدة غير `sers_demo` أو وضع غير `synthetic-only`، ويربط HTTP على `127.0.0.1:3100` فقط. يتطلب Docker على Linux لأن الخادم يستعمل شبكة المضيف للحفاظ على هذا الربط المحلي. لا تستخدم تحويل منافذ أو نفقًا عامًا لهذا العرض.

```bash
export SERS_SECRETS_DIR=/var/tmp/sers-demo-secrets
node scripts/operations/init-secrets.mjs "$SERS_SECRETS_DIR"
docker compose -f compose.demo.yml config --quiet
docker compose -f compose.demo.yml build app
docker compose -f compose.demo.yml up -d --wait --wait-timeout 600 mysql clamav
docker compose -f compose.demo.yml run --rm migrate
docker compose -f compose.demo.yml up -d app worker
docker compose -f compose.demo.yml logs --tail 20 app
```

افتح رابط `/demo?key=...` الذي يطبعه الخادم محليًا. الرمز عشوائي ويتغير عند إعادة التشغيل؛ لا تنشر السجل. اختر المالك أو المراجع. الجلسات مؤقتة في الذاكرة، تنتهي بعد8 ساعات أو إعادة تشغيل الخادم. صفحة `/demo` تبدّل الدور. يرفض الخادم طلبات Host غير المطابق واتصالات غير loopback.

البذرة تنشئ مدرّسة اصطناعية، ومالكًا ومراجعًا، وسنة وفصلين، وتقريرًا بنسخة أولية معتمدة. ترفض قاعدة تحتوي هويات أو مدارس غير اصطناعية. لا تضع بيانات حقيقية فيها. لتجربة الرحلة:

1. ادخل كمالك، وافتح مكتبة الشواهد واختر نطاق المدرسة `SERS Demo — synthetic only` قبل رفع ملف اصطناعي صغير، ثم انتظر حالة الجاهزية بعد الفحص. النطاق الافتراضي شخصي، والتقرير التجريبي يخص المدرسة؛ الربط بين نطاقين مختلفين مرفوض.
2. اربطه بالتقرير، واحفظ المسودة وأنشئ نسخة جديدة، ثم أرسلها للمراجع.
3. عد إلى `/demo` واختر المراجع، وافتح المراجعة واعتمد النسخة.
4. عد إلى المالك وصدّر Word أوPDF. تنزيلهما يمر بمسار مصرح، مع حفظ المحتوى من النسخة الثابتة.
5. افتح الحساب للسنة والفصول والمدرسة، والإشعارات لطلبات المراجعة وقراراتها.

MySQL وClamAV في هذا العرض منشوران على `127.0.0.1:13306` و`127.0.0.1:13310` فقط ليتصل بهما الخادم المحلي. مشروع staging لا ينشر منفذيهما. الإيقاف يحفظ البيانات: `docker compose -f compose.demo.yml down`. إزالة الحجوم `down --volumes` تمحو بيانات العرض نهائيًا؛ استعملها فقط لإعادة تعيين العرض المقصود.

## نسخة متسقة وتجربة استعادة

احتفظ بمتغيرات المشروع نفسها التي شغلت بها Compose. في العرض المحلي أضف:

```bash
export SERS_COMPOSE_MODE=demo
export SERS_DATABASE_NAME=sers_demo
```

في staging اترك `SERS_COMPOSE_MODE` غير مضبوط واستخدم `sers_staging`. إذا عيّنت `COMPOSE_PROJECT_NAME`، يجب إبقاؤه نفسه لأوامر النسخ والاستعادة. الأوامر ترفض أسماء قواعد أخرى.

يجب إيقاف **كل** كاتب: التطبيق والعامل وأي مهمة أو اتصال إداري يعدل القاعدة/الملفات. لقطة SQL وحدها لا تزامن ملفات الشواهد. مثال staging:

```bash
docker compose -f compose.staging.yml stop app worker
export SERS_BACKUP_MODE=quiesced
node scripts/operations/backup.mjs /var/tmp/sers-private-backups
```

للعرض استبدل ملف Compose في أمر الإيقاف بـ`compose.demo.yml`. تحت مجلد النسخ سيطبع الأمر مجلدًا جديدًا يحوي:

- `database.sql`: لقطة MySQL تتضمن المخطط والصفوف.
- `evidence.tar.gz`: **الجذر الخاص كاملًا**، بما فيه `refs` و`preparations` و`tombstones` و`locks` و`blobs`. يسجل tar الروابط الصلبة كمحتوى عادي لتبقى الاستعادة بلا روابط.
- `manifest.json`: بصماتSHA-256 للملفين وعدد الصفوف وchecksum لكل جدول. يُكتب أخيرًا؛ المجلد الذي لا يحتويه غير مكتمل.

المجلد والملفات خاصة بالمستخدم. لا تشارك SQL أو الأرشيف أو ترفعهما كمرفق CI. انقل نسخة مشفرة خارج المضيف وفق سياسة الاحتفاظ واسترجاع المفاتيح الخاصة ببيئتك. فحص SHA يكشف التلف، ولا يثبت مصدر نسخة حصل عليها مهاجم قادر على استبدال manifest أيضًا.

نفّذ التجربة على **مسار المجلد الكامل الذي طبعه أمر النسخ**:

```bash
node scripts/operations/restore-drill.mjs /var/tmp/sers-private-backups/sers-TIMESTAMP-RANDOM
docker compose -f compose.staging.yml start app worker
```

التجربة تنشئ قاعدة عشوائية `sers_restore_*` ومستخدمًا مؤقتًا لا يملك أي صلاحية على القاعدة الأصلية. استيراد SQL يعطل أوامر عميل MySQL المحلية وLOCAL INFILE. يقارن كل جدول بالعدد والchecksum، ويستخرج الأرشيف في مجلد مؤقت مع رفض المسارات المتجاوزة والروابط والأجهزة، وبصلاحيات `0700/0600`. ثم يقرأ عبر المزوّد الحقيقي كل شاهد جاهز وكل مخرج PDF/Word خاص غير ملغى، ويتحقق من النسخة والحجم وSHA-256. يحذف المستخدم والقاعدة والمجلد المؤقت في النهاية. النتيجة JSON يجب أن تحمل `passed:true` وأعداد `privateContentVerified` المتوقعة.

حدود التجربة:100 ألف مرجع ملف، ومليون عنصر أرشيف، و16 GiB بيانات خاصة. إذا تجاوزت النسخة هذه الحدود فلا تعدّ رفض التجربة نجاحًا؛ راجع السعة ونفّذ خطة استعادة مناسبة قبل تعديل الحدود. الأداة لا تستبدل القاعدة الأصلية ولا تنفّذ تحويل خدمة إليها. الاستعادة الفعلية إلى خدمة جديدة تحتاج إجراء قطع مدروس، إعادة ملكية الحجوم للمستخدم10001، اختبار تسجيل الدخول والملفات، ثم تحويل المرور.

إذا فشل النسخ أو الاستعادة، احتفظ بالخدمات الكاتبة متوقفة إلى أن تتأكد من وجود نسخة صحيحة، واقرأ الخطأ والسجلات. لا تحذف النسخة السابقة الجيدة. إذا فشل تنظيف التجربة، افحص فقط قواعد `sers_restore_*` ومستخدمي `sersdrill_*` التي تخص التجربة؛ لا تحذف قاعدة الخدمة.

## التحقق الآلي وحالة التنفيذ

```bash
node node_modules/typescript/bin/tsc -p scripts/operations/tsconfig.json
node --import tsx --test scripts/operations/operations.test.mts
```

سير `.github/workflows/operations.yml` يبني الصورة، ويجهز الحجوم بالمستخدم الصحيح، ويطبق الهجرات على MySQL8.4 اصطناعي، ويستقبل شاهدًا ويفحصه عبر ClamAV الحقيقي، وينشئ Word ويقرؤه بصلاحية المراجع. يفحص جاهزية خادم الإنتاج والعامل ورفض التنزيل غير المسجل، ثم يأخذ نسخة ويستعيدها ويتحقق من وجود شاهد ومخرج واحد على الأقل. يجرب أيضًا dump معدلًا يحاول تنفيذ أمر عميل محلي أو حذف قاعدة المصدر ويثبت رفضهما وبقاء صفوف المصدر. يحذف الحجوم والأسرار والنسخ المؤقتة دائمًا. عناوين OAuth فيCI اصطناعية؛ ذلك لا يثبت تسجيل دخول OAuth فعليًا.

نجحت محليًا اختبارات رفض البيئات غير المناسبة وسلامة manifest والاستعادة الفعلية عبر مزود الملفات ورفض الروابط، وفحص TypeScript لملفات التشغيل. بيئة العمل الحالية لا توفر Docker أوMySQL أوفتح منافذ محلية؛ لذلك لا يُعد تشغيل Compose أواختبار OAuth أوالنشر الخارجي متحققًا إلى أن ينجح سيرCI ويُختبر المضيف المقصود.
