# SERS vNext — سجل القرارات

**الغرض:** منع عودة النقاشات المحسومة بصيغ متعارضة، وإظهار القرارات المفتوحة التي لا يجوز إخفاؤها داخل الكود.

## حالات القرار

- `ACCEPTED`: معتمد ضمن خط الأساس الحالي.
- `PROPOSED`: يحتاج مراجعة الـPR قبل الاعتماد.
- `OPEN`: لم يُحسم ويحتاج مالكًا وموعدًا.
- `SUPERSEDED`: استُبدل بقرار أحدث.
- `DEFERRED`: مؤجل عن الإصدار الحالي.

## آلية حسم قرار مفتوح

كل قرار مفتوح يجب أن يتضمن:

1. المالك.
2. تاريخ الحسم المطلوب.
3. الخيارات.
4. المخاطر والكلفة.
5. التوصية.
6. القرار النهائي.
7. أثره على البيانات والكود والاختبارات والوثائق.
8. ADR مستقل إذا كان معماريًا أو يصعب عكسه.

لا يُحسم قرار حساس ضمن تعليق كود أو محادثة غير مرتبطة بهذا السجل.

## قاعدة التحديث

- عند اعتماد PR المصالحة تتحول قراراته المتفق عليها من `PROPOSED` إلى `ACCEPTED`.
- إذا تغير قرار، لا يُحذف؛ يوضع `SUPERSEDED` ويشار إلى ADR/قرار بديل.
- كل Issue تنفيذية تربط IDs ذات الصلة.
- كل Release Notes تذكر القرارات الجديدة أو المتغيرة.
