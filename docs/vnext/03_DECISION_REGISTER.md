# SERS vNext — سجل القرارات

**الغرض:** منع عودة النقاشات المحسومة بصيغ متعارضة، وتوثيق الحسم الهندسي والمنتجي المعتمد لكل قرار مرتبط بالكود والاختبارات.

## حالات القرار

- `ACCEPTED`: معتمد ومنفذ ضمن خط الأساس الحالي (`main` + PR #43/#44/#45/#46).
- `PROPOSED`: يحتاج مراجعة الـPR قبل الاعتماد.
- `OPEN (OPS/COMMERCIAL)`: يعتمد على بيانات تشغيل خارجية أو اعتماد تجاري/تشغيلي عند النشر الفعلي.
- `SUPERSEDED`: استُبدل بقرار أحدث.
- `DEFERRED`: مؤجل عن الإصدار الحالي.

## القرارات المحسومة هندسيًا والقرارات التشغيلية عند النشر (`O001–O012`)

| ID | القرار المطلوب | الحالة | القرار المعتمد والأثر على الكود والاختبارات |
|---|---|---|---|
| O001 | مزود الدفع والعملات والضرائب وأهلية الحساب التجاري | OPEN (Merchant Keys) — Code Contract Ready | طُبق عقد `PaymentProviderAdapter` بعملة `SAR` وضريبة قيمة مضافة `15%` وتوقيع `verifyWebhookHmacSha256` (`Buffer` خام + نافذة منع إعادة التشغيل) في `server/commerce-sandbox.ts` مع إبقاء الدفع الحقيقي مغلقًا (`livePaymentsAllowed: false`) لحين قرار المالك وربط بيانات التاجر الرسمية |
| O002 | ترتيب وعدد المراجعين وسياسة التفويض | PROPOSED Default Implemented / OPEN (Multi-Reviewer) | طُبق افتراضيًا نموذج المراجع المؤسسي المفرد لكل نسخة مع دعم **إعادة التعيين والتفويض (`domain.review.reassign`)** من قِبل مالك/مدير المدرسة أو مرسل النسخة، ومنع المراجعة الذاتية (`BR01`)، وسجل تدقيق `review.reassigned`، وإشعار المراجع الجديد والسابق؛ سلاسل المراجعة المتعددة تنتظر قرار المالك |
| O003 | ملكية أعمال الموظف عند انتقاله بين المدارس | PROPOSED Default Implemented / OPEN (Final Policy) | تبقى النسخ المعتمدة والمراجعات والشواهد المؤسسية ملكًا للمدرسة الأصلية، ويُتاح **لمُعدّ العمل الأصلي النشط فقط** (دون دور المراجع ودون دورات التقويم) نسخ هيكل مسودته النصية إلى مساحته الشخصية (`domain.work.copyToPersonal`، متكرر بلا ازدواج) مع تجريد تلقائي لشعار المدرسة وهويتها وشواهدها المؤسسية |

| O005 | RTO/RPO وSLOs النهائية | OPEN (OPS/COMMERCIAL) | تمرين النسخ والاستعادة الآلي يعمل في CI (`compose-backup-restore` لـ 39 جدولًا)؛ قياس RTO/RPO الفعلي يتم على خادم الاستضافة عند النشر |

| O007 | مزودو AI وسياسة PII والإقامة | ACCEPTED (Privacy Gate) / OPEN (Prod Key) | الكود يجرّد `reportIdentity` وينقح PII ويطلب موافقة المستخدم؛ اختيار مفتاح المزود الإنتاجي يتم في بيئة النشر |

## قاعدة التحديث

- إذا تغير قرار، لا يُحذف؛ يوضع `SUPERSEDED` ويشار إلى القرار البديل.
- كل PR تنفيذي يربط معرّفات القرارات ذات الصلة ويحدث هذا السجل بالتزامن مع الاختبارات.
