# 7. المصادر الرسمية المطلوبة قبل التنفيذ التفصيلي

يُنشأ داخل Official Requirements Registry سجل مصدر لكل موضوع، ومنها:

- مسميات ووظائف وتكليفات المدرسة.
- الأداء الوظيفي ودوراته ونماذجه.
- التقويم الذاتي والمدرسي وإصداراته.
- خطط التحسين والخطط التشغيلية.
- NAFS ونواتج التعلم عند دخولها النطاق.
- حماية البيانات والخصوصية والسحابة والأمن السيبراني.
- التعاملات والتوقيع الإلكتروني إذا دخلت الحجية النظامية.

لا تنسخ المتطلبات الرسمية كنص ثابت داخل الكود؛ تحفظ بإصدار وتاريخ نفاذ ومصدر ونطاق تطبيق.

# 8. قواعد الثقة والتتبع

لكل claim مهم يضاف:

- `source_type`
- `source_reference`
- `source_date`
- `last_verified_at`
- `confidence`
- `owner`
- `decision_status`
- `implementation_reference`
- `test_evidence`

## درجات الثقة

| الدرجة | المعنى |
|---|---|
| High | كود/اختبار/مصدر رسمي/ملاحظة مباشرة قابلة لإعادة الفحص |
| Medium | وثيقة جيدة أو فيديو واضح لكن بلا وصول كامل للنظام |
| Low | تفريغ آلي أو claim تسويقي أو ذاكرة محادثة بلا Artifact |

# 9. مفقودات يجب عدم ادعاء اكتمالها

- مراجعة حرفية لكل محادثة ChatGPT تاريخية.
- إثبات اختبار استخدام كامل للنموذج ذي 32 شاشة.
- مصفوفة رسمية نهائية لكل وظيفة ومعيار وإصدار.
- تجربة مدفوعة/داخلية لكل منافس.
- قرار نهائي للدفع والضرائب والإقامة والاحتفاظ.
- دليل Production readiness.
- Restore drill وRTO/RPO فعليان.
- Golden Arabic PDF/Word/QR معتمد.
- إغلاق كل حالات F01–F20.

إظهار هذه المفقودات جزء من جودة المشروع، وليس نقصًا في التقرير.

---

# 10. آلية إضافة مصدر جديد

1. لا يضاف claim وحده؛ يضاف المصدر وتاريخه.
2. يحدد هل المصدر ثابت أم متغير زمنيًا.
3. يربط بمتطلب أو قرار أو Issue.
4. توثق درجة الثقة والقيود.
5. إذا تعارض مع مصدر أعلى، يُفتح قرار ولا يُستبدل بصمت.
6. عند انتهاء صلاحية المصدر، لا يحذف؛ يوسم `superseded` ويشار إلى البديل.
