# B04 — عقد رفع الشواهد الآمن

التاريخ: 2026-10-21. الحالة: تصميم للتنفيذ والمراجعة؛ ليس مسار رفع إنتاجيًا منفذًا.
المراجع: #17، R04/R05/R18، F09–F12/F18، وسجل التسليم 07.

## الوضع الحالي المثبت من الكود

- `server/routers.ts`، `file.upload`: تفويض portfolio ثم فحص قبول ثم storagePut ثم كتابة uploadedFiles. مفتاح عشوائي جديد لكل محاولة، وفشل الكتابة بعد الرفع يسجل console.warn فقط؛ لا توجد مصالحة دائمة في هذا المسار.
- `server/db.ts`، `createUploadedFile`: يعيد التحقق من ملكية portfolio داخل transaction مع FOR UPDATE بعد التخزين؛ هذا ضمان قائم يجب الحفاظ عليه. حذف metadata الحالي لا يثبت حذف blob، ولا يغني عن نتيجة حذف مشروطة موثقة.
- `server/storage.ts`: proxy يرفع ويعيد URL؛ لا يثبت خصوصية الكائن أو يدعم هنا head/checksum/delete مشروطًا. لا يجوز اعتباره adapter حجر خاص دون إثبات قدرات المزود.
- `server/upload-validation.ts`: حد الشاهد الحالي 16 MiB وفحص توقيعات أولي؛ ليس فحص برمجيات خبيثة أو تحققًا كاملًا لحاويات Office.
- `server/domain-router.ts`: createReference يقبل link/text فقط. إضافة رفع الملفات تحتاج عقدًا مستقلًا، لا تمرير storageKey من العميل إلى createAssetForUser.
- `server/domain-db.ts`: نطاق ملكية أصل وربط متوافق مع العمل موجود؛ unlink يزيل الربط. يجب الحفاظ على عدم حذف الأصل عند فك الربط.

## حدود الدفعة

مسار جديد خلف feature flag، يبدأ ببيانات اصطناعية وadapter اختباري خاص. لا تحويل تلقائي للروابط القديمة إلى أصول موثوقة، ولا تغيير للمسار القديم قبل بوابة التوافق. لا يُفعّل المسار إذا لم تتوافر الخصوصية أو الفحص المطلوب. O006 (المزود والإقامة) وO004 (الاحتفاظ) مفتوحان؛ لا يختار هذا التصميم مزودًا أو مدة إنتاجية.

## عقد الطلبات

كل المسارات مصادقة، والتفويض يعاد في كل عملية، لا عند إنشاء intent فقط. تستخدم معرفات عشوائية، ولا تقبل bucket/key/url من المستخدم.

| العملية | المدخل | المخرج والسلوك |
|---|---|---|
| begin | idempotencyKey، نطاق الملكية، workId اختياري، اسم عرض، حجم ونوع معلنان | intentId، expiresAt، state؛ يتحقق من العضوية والعمل ويحجز quota ذريًا |
| receive | intentId وبايتات ضمن سقف الخادم | حالة الاستلام فقط؛ stream محدود إلى حجر خاص، لا URL عام |
| complete | intentId | حالة معالجة أو assetId جاهز؛ الحجم والنوع والـSHA-256 مشتقة من البايتات بالخادم |
| status | intentId | حالة وسبب عام قابل للإجراء؛ بلا مفاتيح تخزين أو تفاصيل فحص حساسة |
| cancel | intentId | إلغاء منطقي وإدراج مهمة تنظيف؛ لا حذف متزامن افتراضي |
| download | assetId | تفويض read حديث وحالة ready ثم استجابة محمية؛ لا تنزيل من intent |

الأخطاء: BAD_REQUEST لمدخل غير صالح، CONFLICT لإعادة مفتاح بمحتوى مختلف أو انتقال متعارض، TOO_MANY_REQUESTS للحصة، وعدم إتاحة عام لمعرف غير مملوك/منتهي. تعطل المزود أو الفحص يعيد حالة قابلة لإعادة المحاولة دون ادعاء نجاح. لا يعتمد checksum المعلن من العميل كدليل.

## آلة الحالات وضمانات التزامن

| من | إلى | الشرط والمالك |
|---|---|---|
| issued | receiving | الخادم يعيد التفويض والصلاحية، ويحجز lease بعملية CAS على revision |
| receiving | quarantined | إثبات كائن مكتمل ثابت النسخة والحجم والـhash؛ العامل فقط |
| quarantined | validating | عامل يملك lease محدود المدة |
| validating | ready | فحص مطلوب ناجح، إعادة تفويض، وكتابة Asset + نتيجة intent + outbox في معاملة واحدة |
| validating | rejected | عدم مطابقة/فحص فاشل؛ لا Asset جاهز ولا رابط تنزيل |
| issued/receiving/quarantined/validating | cancelled/expired | CAS؛ إن وجدت عملية كتابة متزامنة تُصالح أولًا ولا يحذف الكائن عميانًا |
| receiving/validating | الحالة نفسها | عطل مؤقت: attempts وnextAttemptAt، ولا انتقال نجاح وهمي |

ready/rejected/cancelled/expired حالات نهائية لهذا الطلب. فشل فحص نهائي يتطلب intent جديدًا. انتهاء lease ليس دليلًا على فشل الكتابة؛ يعاد فحص حالة المزود والمعاملة. لا يعاد فتح cancelled بالـretry.

## التخزين الدائم والـidempotency

جدول uploadIntents المقترح: id، actorUserId، ownerType/ownerId، workId، idempotencyKeyHash، requestFingerprint، state، revision، expiresAt، leaseUntil، reservedBytes، actualBytes، detectedMime، sha256، objectKey، objectVersion، scanPolicyVersion، scanResult، assetId، attempts، nextAttemptAt، errorCode، timestamps.

قيد فريد على (actorUserId، ownershipScope، idempotencyKeyHash). fingerprint يشمل كل المدخلات الدلالية بما فيها الهدف والحجم والنوع والاسم. نفس المفتاح والبصمة يعيد نفس intent/asset، واختلافها يرفض؛ المفتاح لا يعاد استخدامه بعد الانتهاء ما دام سجل الإلغاء محفوظًا وفق سياسة الاحتفاظ. hash مطابق لملف آخر يتيح اقتراح تكرار داخل النطاق فقط، ولا يدمج الملكية أو يمنح صلاحية بين مستخدمين/مدرستين.

حجز quota وإنشاء intent في معاملة واحدة؛ تحرير الحجز مرة واحدة بانتقال ذري، مع احتساب المساحة المحجورة ضمن الاستخدام حتى الحذف المثبت. قيود الحصة والمعدل لكل مستخدم ونطاق تخزين، مستقلة عن حدود مشاركة التقارير.

## عقد المزود والفحص

adapter خادمي: putPrivate(key, stream, maxBytes, conditionalCreate)، head(key, version)، readPrivate(key, version)، deleteIfVersion(key, version). النتائج تميز confirmed/missing/unknown، وتعيد version ثابتًا وحجمًا؛ SHA-256 يحسبه الخادم ولا يفترض أن ETag هو hash. انتهاء المهلة يعيد unknown لا missing. الاعتمادات لا تغادر الخادم.

سياسة الفحص: allowlist، مقارنة الحجم الفعلي، parser محدود الوقت والذاكرة وعدد العناصر والحجم المفكوك ونسبة الضغط، كشف تشفير/حاويات غير قابلة للفحص ورفضها حتى سياسة صريحة، فحص malware مطلوب قبل ready. الأعطال/نتائج unknown تبقي الحجر. تحفظ نتيجة الفحص وإصداره دون تسجيل محتوى الملف. معاينات الصور مشتقات منفصلة منزوع منها metadata الحساسة؛ الأصل خاص ويحفظ كما هو، خصوصًا الفيديو. لا يدعى تنفيذ CDR قبل وجود خدمة واختبار لها.

التنزيل المحمي يبدأ بإعادة تفويض داخل الخادم. إذا اختير signed URL لاحقًا يوثق صراحة أن سحب العضوية لا يبطل URL الصادر فورًا، وتحدد مدة صلاحية معتمدة؛ لا يعد ذلك ضمان سحب فوري. لا تعرض أصول الحجر عبر CDN أو QR.

## المصالحة والتنظيف

تُكتب نية الرفع قبل أي كتابة تخزين، لذلك يمكن للعامل اكتشاف الكائن حتى إذا فشل تحديث DB بعدها. جدول مهام دائم مع unique(intentId, operation, objectVersion)، lease، attempts، nextAttemptAt، آخر خطأ مصنف؛ backoff محدود وإحالة يدوية بعد استنفاد المحاولات، بلا حلقات غير محدودة.

عند timeout commit: أعد قراءة intent/asset من مصدر DB الموثوق؛ إن تعذر الحسم اتركه pending، ولا تحذف. قبل الحذف: اقفل سجل intent، تحقق من نهائيته ومن عدم وجود Asset أو روابط أعمال أو مراجع نسخ/مخرجات حية أو legal hold، وثبت tombstone يمنع نشر/ربط الكائن ذاته. بعد ذلك حذف مشروط بالنسخة؛ النسخة المختلفة أو الحالة unknown تؤجل المصالحة. لا يعتمد العامل على prefix listing وحده. outbox يضمن أن حدث ready يظهر فقط مع المعاملة الناجحة.

## مصفوفة قبول ملزمة للتنفيذ

| ID | الحالة | نتيجة يجب إثباتها |
|---|---|---|
| U01 | رفع صحيح ثم complete مرتين | أصل واحد ونتيجة ثابتة وبايتات مطابقة |
| U02 | begin متزامن بنفس المفتاح | intent واحد وحجز حصة واحد |
| U03 | نفس المفتاح ومدخل مختلف | CONFLICT دون كتابة تخزين |
| U04 | مستخدمان ومدرستان ومحاولة تبادل intent/asset | رفض قراءة/كتابة/تنزيل عبر النطاق |
| U05 | سحب العضوية أثناء الرفع/الفحص | لا نشر ولا تنزيل؛ تحرير آمن بعد المصالحة |
| U06 | نجاح put وفشل DB أو انقطاع رده | سجل intent يسمح بالاستعادة دون أصلين أو حذف متسرع |

| U10 | عاملان أو تعطل العامل بعد حذف ناجح | lease/CAS وحذف idempotent مشروط بالنسخة |
| U11 | مرجع حي أو نسخة تخزين مختلفة أثناء التنظيف | لا حذف؛ تسجيل سبب التأجيل |

| U13 | فيديو وإعادة محاولة بعد انقطاع الشبكة | hash وعدد بايتات الأصل ثابتان؛ لا QR محلي |
| U14 | نفاد quota أو intent flood | رفض قبل تخزين إضافي؛ لا تسرب حجوزات |

## ترتيب التنفيذ وبوابة الإغلاق

1. migration للجداول والقيود + repository transactional، واختبارات MySQL للتزامن والـrollback U01–U08.
2. منسق حالات + adapter ذاكرة للاختبار مع حقن الأعطال، وعامل مصالحة U06–U11.
3. اختيار مزود وADR للخصوصية/الإقامة والاحتفاظ بواسطة مالك المنتج قبل adapter الإنتاجي؛ إثبات contract tests على بيئة معزولة.
4. ربط UI للحالات والإلغاء وإعادة المحاولة، ثم اختبارات متصفح U04/U05/U09/U13/U14.
5. تفعيل محدود ببيانات اصطناعية، سجل قياسات عمر الحجر وفشل الفحص وتأخر المصالحة، وتجربة rollback توقف intents الجديدة وتسمح بتصريف الأعمال القائمة.

لا يغلق B04 بمجرد هذه الوثيقة. الإغلاق يتطلب تنفيذ المصفوفة وإثبات خصائص المزود والفحص والاحتفاظ، ومراجعة مستقلة قبل تمكين بيانات حقيقية.

مراجعة مستقلة: فحص وكيل ثانٍ مسارات routers/db/storage/domain دون تعديلها؛ تأكدت إعادة التفويض الحالية وأُضيفت إلى خط الأساس، واتفق الفحص على فجوات idempotency والمصالحة وخصوصية adapter. هذه مراجعة تصميم وكود وليست نتيجة تشغيل للمسار المقترح.
