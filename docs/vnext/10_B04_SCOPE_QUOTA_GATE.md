# B04 — حجز المساحة وصلاحيات نطاق الرفع

2026-10-21. دفعة داخلية قبل استقبال البايتات، وليست تفعيل رفع إنتاجي.

## السلوك المنفذ

- begin يقبل نطاقًا شخصيًا أو مدرسة وworkId اختياريًا. المدرسة يجب أن تكون active وعضوية المنشئ active بدور owner/admin/member؛ reviewer غير مخول. العمل غير محذوف ويطابق نطاق الملكية. يعاد التفويض عند begin/status/cancel.
- طلب المدرسة يظل مقروءًا/قابلًا للإلغاء بواسطة منشئه فقط مع استمرار عضويته، حتى لو شاركه أعضاء آخرون حصة المدرسة. هذا تقييد مقصود لهذه الدفعة، وليس واجهة إدارة مدرسية لجميع الطلبات.
- ميزانية upload_quota_budgets تُهيأ بإجراء خادمي موثوق. لا قيمة إنتاجية افتراضية ولا endpoint لتغييرها. غيابها يمنع طلبًا جديدًا. الحجز يجمع حد البايتات وحد عدد الطلبات النشطة، داخل معاملة إنشاء الطلب نفسها.
- القيد الفريد أصبح actor/scope/key. نفس المفتاح في نطاق مختلف طلب مستقل، ونفسه داخل النطاق مع محتوى مختلف تعارض. لا تضاعف إعادة المحاولة الحجز.
- إلغاء/انتهاء issued يحرر الحجز مرة واحدة. reservationHeld يحمي التكرار، وتعارض العدادات يرفض المعاملة كاملة. الساعة من قاعدة البيانات.
- expireUploadIntentsForScope عملية صيانة موثوقة محدودة حتى100 طلب، تعيد الحجز للطلبات المنتهية دون صلاحية مستخدم مسحوبة. لم يضاف scheduler أو endpoint؛ يجب توصيل تشغيلها ومراقبتها قبل التفعيل. تأخر تشغيلها قد يرفض طلبات جديدة بسبب حجوزات منتهية باقية.
- ترتيب الأقفال ثابت: مستخدم/مدرسة، عضوية، عمل، ميزانية، طلب. عامل الانتهاء يأخذ ميزانية ثم طلب، ولا يصعد لأقفال الصلاحيات.

## الترحيل والتوافق

0013 يضيف النطاق وميزانيات الحجز. السجلات القديمة personal، وبصمتها القديمة محفوظة. issued القديمة تنتهي مع زيادة revision لأن الدفعة السابقة لم تحجز مساحة ولم ترفع بايتات؛ cancelled/expired تبقيان بحالتهما. لا تنشأ ميزانية تلقائيًا. ينشأ الفهرس الفريد الجديد قبل إسقاط القديم لأن FK المستخدم يعتمد فهرسًا يبدأ actorUserId. 0014 يضيف فهرس scope/state/expiry/id للصيانة.

اختبار upgrade ينشئ قاعدة مؤقتة فريدة داخل خدمة CI، يطبق الترحيلات حتى0012، يزرع الحالات الثلاث، ثم يطبق التحديث مرتين ويفحص الحالة والنطاق والحجز. يحذف قاعدة الاختبار الخاصة به فقط. اختبار التكامل يغطي التزامن وفصل المدارس وسحب العضوية ورفض العمل غير المطابق ونفاد الحصة والتراجع عن فشل تحرير الحجز. نتائج التشغيل مرتبطة برأس PR ولا تعتبر هذه الوثيقة وحدها نجاحًا للاختبارات.

## حدود الانتقال

الحجز هنا لطلبات ما قبل التخزين فقط، ولا يقيس ملفات إنتاجية قائمة أو storedBytes، ولا يفرض معدل طلبات زمنيًا. لا يجوز استخدام التحرير المباشر بعد رفع blob؛ استقبال البايتات يحتاج حالات/leases وحساب المساحة حتى الحذف المثبت، ثم فحص/مصالحة ونشر منفصلة. لا scanner ولا مزود خاص ولا تنزيل ولا UI في هذه الدفعة.

البوابة التالية بعد نجاح CI ومراجعة مستقلة: عقد adapter خاص قابل لاختبارات الفشل، ثم استقبال محدود بالبايتات وحالات حجر دائمة. O004/O006 وقرار scanner مفتوحة قبل production. B04 وPilot غير مغلقين.
